# 联网卡片对战游戏

目标: 建立商业级的可扩展的，联网卡片对战系统。

# 对战规则
## 游戏准备
- 游戏人数2。
- 每人卡组40-60张。
- ID重复的卡片不超过3张
- 5张及其以下的“传说卡”

## 卡片信息
卡片通用属性：
- 卡片类型：人物卡、策略卡、物品卡、传奇卡。
- 卡片属性：理性、神性、灵性。(只能为其中一种)
- 卡片名称
- 卡片字段：（一组字符串的List）
- 卡片范畴：数学、科学、文艺、哲学、神秘
- 费用
- 效果：（代码层面上为HashMap key为e1,e2 以此类推。value为Effect效果对象）

人物卡独有属性：
- 攻击力

策略卡独有属性：
- 策略属性：普通、诡计、瞬时

物品卡独有属性：
- 物品属性：普通、存留。

## 游戏阶段
- 回合开始阶段
- 抽卡阶段
- 回收阶段
- 主要阶段1
- 战斗阶段
- 主要阶段2
- 回合结束阶段

## 每个玩家区域的概念
- Desk 卡组
- Hand 手卡（上线20张）
- ForEnd Zone 前场（每个玩家5个）
- BackEnd Zone 后场（每个玩家5个）
- Cost Zone 费用区
- Hp 生命值
- Grave 墓地
- RealPoint 真实点数

## 费用系统

- 支付费用：将对应数目的手卡放置到费用区内。
  - 如：5费登场。就是将5手卡放入到费用区内。要使用的卡本身不能算作费用。
  - 使用的费用不能大于卡片的描述。不能1费的卡，放置3张卡到费用区
- 需要支付费用可以使用RealPoint代替（玩家可以自行选择使用手卡充当费用和使用RealPoint充当费用的比例）
- 在cost区内的卡。依旧可以使用。也就是说在费用区的卡，依旧可以支付费用登场，或者使用。但是本身不能当做费用放置到费用区（因为已经在费用区了）
- 在cost区的卡如果要登场，在登场前仍然占用一个位置。
- cost区的最多有6个位置。

## 战斗系统。

- 前场上的人物卡才能战斗。
- 战斗时只能选择对手前场的卡或者对手玩家进行攻击宣言。
- 当对手前场有卡时，只能选择对手的卡进行战斗。（除非有卡效果特别说明）
- 发起战斗的一方进行战斗成功时（无论输赢）都可以获得一点RealPoint
- 当直接攻击时
    - 自己没有RealPoint时（RealPoint=0时） 获得1点RealPoint
    - 自己有RealPoint时可以选择使用n点RealPoint对对手造成伤害。（n为进攻方玩家自己选取，不大于RealPoint的值）。攻击结算后，扣除攻击方的n点RealPoint
- 当血量不足时， 血量不足的玩家必须使用realPoint减少伤害。（强制使用）
- 当血量小于等于0时玩家失败 游戏结束，对方获胜。
- 战斗失败的卡进入墓地。
- 如无特殊说明，一张卡一回合只能攻击一次。
- 战斗阶段时，如果选中的攻击目标发生变化，攻击回滚。

## 回收

- 回收的意思是：从费用区将卡加回到手卡
- 回收阶段时，要进行回收：回收卡数为对手前场上费用最高的卡的费用X
    - 如果X比费用区的已有卡片个数大就全部回收（强制）
    - 如果X比费用区的已有卡片个数小时，由回收回合的当前玩家选择回收那些卡。个数必须为X。
    - 这个值为0时不回收（对手前场没有卡的情况下也不能回收）

## 抽卡
- 抽卡阶段，当前玩家从卡组抽取一张卡。
- 任何时间，当要玩家要抽卡时，而卡组没有卡片可以抽取，那名玩家游戏失败。

## 游戏内限制

- 初始Hp为5,最多为6
- 费用区最多6张卡
    - 当费用区满时，不能通过从手卡放到费用区来支付费用（无法进行这个操作），换句话说只能支付RealPoint来登场或者发动特定效果。
- 手卡最多为20张
    - 超过20张后每次新加入的卡进入弃牌堆
- RealPoint 最高为6。当RealPoint为6后不在获取新的RealPoint而是抛出溢出事件。（有的卡可以根据事件发动效果）


## 卡片ID的定义原则
- ID 为 : S[卡包号]-[卡片类型]-[卡编号]
- 卡包号：为三位补齐。如001,002等,特别的测试卡包为000
- 卡片类型：人物卡（C）、策略卡(S)、物品卡(I)、传奇卡(L)。
- 卡编号：为三位补齐，如001,002等

举例： S001-C-001 为第一个卡包的第一个人物卡。


# 部分设计和原则

- 在Lua的API加载时可以使用unsafe的写法。
- 游戏中使用的卡片由Lua脚本定义。可扩展。
- 脚本只描述效果，不执行任何逻辑。执行逻辑交给Rust来完成。
- 游戏不使用中心服务器进行计算。是点对点通讯，底层使用tcp。
- 在游戏启动后，启动一个服务端进行监听。
  - 本地游戏，创建一个AI的客户端进行链接。在创建一个交互的服务端进行链接。
  - 远程链接，链接对方的服务端，或者链接自己的服务端进行对战。
- 需要一个额外的独立的服务器，仅仅用作联网对战的匹配，版本更新检查等。
- 需要实现视频回放功能。
- 本地对战可以中途保存，并恢复。（残局系统）
- 游戏的客户端定义良好的API,应该可以扩展为不同的客户端实现，比如命令行的TUI或者是bevy的页面客户端，或者网页版，或者unity。
- 有良好的日志打印。
- 询问客户端操作时应该有超时时间。有每个操作的相应时间，和单局的总时间。超时判负。
- 每局的相关时间都可以单独设置，（每局都可以在开始前调整规则）

# 效果和连锁系统。
- 连锁规则：当前玩家发动卡的效果后可以进行连锁。规则是当前玩家先选择。当前玩家选择Pass或者超时后。连锁权利到另外一名玩家哪里，直到他选择完毕后。权利再返回到对方那里。直到双方都没有继续连锁。在Effect内结算效果对战。FILO的原则。
- 瞬时策略卡，会马上计算当前卡片的效果，之后把连锁权交给对手。
- 默认行为。（策略卡）
  - 普通策略卡和物品卡只能在后场使用。（非存留的使用后进入墓地。）
  - 后场已经存在卡的位置也可以使用策略卡、物品卡、传奇卡。相当于顶掉之前的卡，原来放置的卡进入墓地。
  - 存留的策略卡，在场上的效果一直有效。
  - 诡计的策略卡，只能才手卡中才能发动。
  - 瞬时的策略卡，在连锁结算时不能发动（所有的卡的效果都不在连锁结算时主动发动）在连锁中，可以发动，发动后将连锁权限马上交给对手。
## 效果
对象的定义。（仅仅参考）
pub struct Effect {
pub trigger: Trigger,              // 时点
pub optional: bool,                // 是否“可以发动”
pub activation_limit: Option<ActivationLimit>, //  触发的限制
pub conditions: Option<Condition>,    // 触发条件
pub choices: Vec<Choice>,       // 选择目标
pub actions: Vec<Action>,          // 实际效果
pub costs: Option<CostChoice>,       // 费用要求
}

- 时点：
  - 全部阶段。（默认）
  - 回合开始时，
  - 自己主要阶段，
  - 对方主要阶段，
  - 双方主要阶段，
  - 攻击时，
  - 暴露时，
  - 破坏时，
  - 登场时，
  - 回合结束阶段
- 是否可以发动。如果不是的话，不询问玩家，效果直接生效
- 触发的限制 
  - 一回合一次
  - 同名卡一回合一次
- 触发条件，需要设计。满足可以在lua内自由组合定义，并可以or和and的逻辑。生成语法树，并可以解析执行。比如：
    1. 对手手卡大于自己的手卡时才能发动
    2. 自己Cost区内属性理性的卡数目（简称理性值）大于3才能发动

- Action 为实际执行的效果。配合好Choice选择目标使用。比如
  1. 自己抽一张卡。
  2. 选择一名玩家增加一点RealPoint
  3. 破坏对手场上的理性属性的卡

- 费用要求。只发动效果除了支付卡面信息的费用外，还需要支付的类似费用的内容。（发动前需要先支付Cost。Cost支付后不能回滚）是一个定义，需要用户选择比如：
  1. 支付场上一张卡发动
  2. 支付两张手卡发动
  3. 将两张Cost区的卡丢入墓地发动。

- 转成可读的文本。卡片定义的效果对象，可以转成不同语言的文本，完全依赖算法拼成效果，而不直接描述。
